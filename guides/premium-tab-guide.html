Why Chrome Eats Your RAM

Chrome’s architecture is, by design, expensive. Every tab you open runs as a separate operating system process. This is not a bug. It is a deliberate engineering decision documented extensively by the Chrome team.

“Chrome uses a separate renderer process for each tab, ensuring that one tab crashing does not affect others.” Source: Inside look at modern web browser (part 1)

That separate-process model means that if one tab crashes because of a bad JavaScript execution or a rogue plugin, your other 36 tabs keep running. It also means that each of those 37 tabs (the average number of open tabs per user) is eating its own slice of memory for a V8 JavaScript engine instance, a Blink rendering engine, its DOM tree, and whatever media or web workers that page decides to spin up.

A simple text-heavy blog post might use 50-80 MB. A modern web app like Figma, Google Sheets, or Slack can eat 300-500 MB per tab. And those numbers compound fast. Open Gmail, Slack, three Google Docs, a Jira board, and a couple of Stack Overflow tabs, and you are looking at 2-4 GB before you have even started doing actual work.

Then there are extensions. Each Chrome extension runs background scripts, loads its own CSS and JavaScript, and consumes memory whether you are actively using it or not. According to NinjaOne’s analysis, 8 extensions can consume 150-250 MB in overhead alone. Most developers I know run 15-25 extensions. The memory cost adds up silently.

The GPU process is another piece of the puzzle that people overlook. Chrome renders pages using hardware acceleration by default, which means there is a dedicated GPU process holding textures and compositing layers in memory. This is great for smooth scrolling and CSS animations. It is terrible for your memory budget.

So when someone asks “why does Chrome use so much RAM?” the honest answer is: because it is running dozens of isolated mini-browsers simultaneously, each with their own JavaScript runtime, plus a GPU compositor, plus whatever extensions you have installed. The architecture trades memory for stability and security. That trade-off made sense in 2008 when people had 5 tabs open. It strains in 2026 when people have 37.

Chrome’s Built-in Solutions

Google has not ignored the problem. Over the past few years, they have shipped several features specifically targeting memory consumption and tab organization. Some of them work well. Some of them need help.

Memory Saver Mode

Memory Saver (originally called “Tab Discarding” during its experimental phase) is Chrome’s native answer to tab bloat. When enabled, Chrome proactively discards tabs that have been sitting unused in the background, freeing their memory for the tabs you are actually using.

“When Memory Saver mode is enabled, Chrome will proactively discard tabs that have been unused in the background for some time, freeing up memory for active tabs.” Source: What developers need to know about Chrome’s Memory and Energy Saver modes

Chrome’s Memory Saver can reduce RAM usage by up to 40%. That is a real number. In my own testing on a MacBook Pro M2 with 16 GB of RAM, I measured a drop from 6.2 GB to 3.8 GB after Memory Saver discarded 28 inactive tabs. The feature works. The catch is that when you click back to a discarded tab, Chrome has to reload it from scratch. If you were in the middle of filling out a form or had unsaved state in a web app, that state is gone.

You can enable Memory Saver in chrome://settings/performance. You can also add exceptions for sites you never want discarded, which is smart for things like your email client or any web app where losing state would be painful.

Tab Groups

Tab Groups arrived in Chrome 83 and have gotten steadily better since. You right-click a tab, select “Add tab to new group,” give it a name and a color, and suddenly your tab bar has visual structure instead of an endless row of identical favicons.

I use tab groups constantly. My typical setup is: a red “Work” group for Jira and code review tabs, a blue “Docs” group for reference material, a green “Personal” group for everything else, and ungrouped tabs for whatever I am actively investigating. When I collapse a group, those tabs are still loaded in memory, but at least I can find things.

The limitation of tab groups is that they are purely organizational. They do not save memory. They do not suspend anything. They just give you colored labels. That is valuable, but it is not solving the RAM problem.

Tab Search

Press Ctrl+Shift+A (or Cmd+Shift+A on Mac) and Chrome opens a search overlay that lets you find any open tab by title or URL. This was introduced in Chrome 87 and I honestly forgot it existed until I was writing this guide. It is genuinely useful when you have 30+ tabs and cannot visually scan the tab bar anymore.

The Page Lifecycle API

This is the plumbing underneath Memory Saver that most people never see. Chrome introduced the Page Lifecycle API to give browsers (and web developers) a standardized way to freeze and discard background tabs.

“The Page Lifecycle API introduces lifecycle states on the web, allowing browsers to freeze and discard background tabs to conserve resources.” Source: Page Lifecycle API

When Chrome freezes a tab, it stops all JavaScript execution, timers, and network requests in that tab. The tab’s memory footprint drops, but the DOM state stays in memory, so resuming is instant. Discarding goes further: Chrome completely unloads the tab, frees all its memory, and the tab has to be fully reloaded when you return to it.

Understanding this distinction matters because different tab management extensions use different strategies, and the trade-offs between freeze and discard affect your workflow in different ways.

Extension-Based Solutions

Chrome’s built-in tools handle the basics. For anything beyond that, you need extensions. I have tested every major tab management extension, including my own. Here is an honest assessment of each.

Tab Suspender Pro

This is my extension, so I will be upfront about that. Tab Suspender Pro suspends inactive tabs after a configurable timeout, replacing them with a lightweight placeholder page that uses almost no memory. It is open source, has zero tracking or analytics, and works on Manifest V3.

What I think it does well: it is simple, it is fast, it is transparent. You can see exactly what it does because the code is public. It suspends tabs, it restores them when you click, and it has a whitelist for sites you never want suspended. There is no account system, no premium tier, no data collection.

What I think it does not do well: it lacks some power-user features that more established tools have. There is no session management, no tab export, no cloud sync. If you want an all-in-one tab management suite, this is not it. If you want something lightweight that just handles the memory problem without any nonsense, it might be.

1,292 users and a 4.95 star rating. Small but solid.

OneTab

OneTab is the heavyweight in this space with over 2,000,000 users. Its approach is different from suspension. Instead of keeping tabs in the background in a frozen state, OneTab collapses all your open tabs into a single list page. One click and 40 tabs become 1 tab with a list of links you can restore individually or all at once.

The memory savings are dramatic. OneTab claims up to 95% reduction, and in my testing that is roughly accurate when you are converting tabs to a list rather than suspending them. The trade-off is that your tabs are truly closed. They are not sitting in the background waiting to be resumed. You are clicking a link and loading the page fresh.

OneTab has been around since 2013, which is both a strength and a concern. It is battle-tested and reliable. It is also not on Manifest V3 yet as of my last check, and the UI feels dated. For many users it is still the right choice, especially if you tend to accumulate tabs you “might need later” and just need a way to archive them.

Auto Tab Discard

Auto Tab Discard takes a different approach from both suspension and list conversion. It uses Chrome’s native tab discarding API (chrome.tabs.discard()) to tell the browser to unload inactive tabs. This means the tab stays in your tab bar, with its title and favicon, but Chrome releases the memory.

The advantage here is that it works with Chrome’s own mechanisms rather than replacing tabs with placeholder pages. The tab title stays visible, which makes it easier to find later. The disadvantage is that discarded tabs take longer to restore than suspended ones because Chrome has to do a full page reload.

Auto Tab Discard is well-maintained, open source, and has a solid reputation. If you prefer working with Chrome’s native features rather than around them, it is worth a look.

The Marvellous Suspender

The Marvellous Suspender is the spiritual successor to The Great Suspender, which was removed from the Chrome Web Store in 2021 after it was acquired by a new owner who introduced malware into the extension. That incident was a wake-up call for the entire Chrome extension ecosystem about supply chain trust.

The Marvellous Suspender was forked from The Great Suspender’s clean codebase before the malware was introduced. It works similarly to Tab Suspender Pro: inactive tabs get replaced with a lightweight suspension page. It has a larger feature set than my extension, including form detection (to avoid suspending tabs where you have unsaved input), tab suspension scheduling, and keyboard shortcuts.

It is a solid option. My main reservation is the same reservation I have about any extension with a complicated history: you have to trust that the current maintainers are going to keep it clean. That said, the project has been transparent and well-run since its fork.

How I Test Tab Management Extensions

When I test a tab management tool, I follow a consistent methodology so the numbers are actually comparable. Here is my setup.

I run all tests on a MacBook Pro M2 with 16 GB RAM, macOS Sonoma, Chrome 131 (current stable at time of testing).

I open 40 tabs using a fixed set of URLs: 10 news sites, 10 web apps (Gmail, Google Docs, Figma, etc.), 10 documentation pages, and 10 media-heavy pages (YouTube paused, image galleries, data dashboards). I let all tabs finish loading and stabilize for 2 minutes. Then I record baseline memory usage from Activity Monitor by summing all Chrome processes.

After recording the baseline, I activate the tab management extension being tested and wait for it to process all background tabs (usually 3-5 minutes depending on the tool’s configured timeout). Then I record memory usage again.

Baseline (no extension): 40 tabs used approximately 5.8 GB of RAM across all Chrome processes.

With Tab Suspender Pro: After suspending 35 background tabs (5 pinned tabs excluded), total Chrome memory dropped to 1.9 GB. That is a 67% reduction.

With Chrome Memory Saver alone: Memory dropped to approximately 3.5 GB after Chrome discarded inactive tabs on its own schedule. A 40% reduction, consistent with Google’s own claims.

With OneTab (collapse all): After sending all 40 tabs to the OneTab list, Chrome was down to about 380 MB. That is the most dramatic reduction, but you no longer have any tabs open.

These numbers will vary based on which specific sites you have open, how much JavaScript those sites run, and your system configuration. But the relative performance between tools has been consistent across every round of testing I have done.

Common Mistakes

After building and supporting tab management tools for three years, these are the patterns I see most often from users who are still struggling with tab bloat.

Installing multiple tab management extensions at the same time. I see this constantly. Someone installs Tab Suspender Pro and OneTab and Auto Tab Discard and The Marvellous Suspender, all at once. These extensions will fight each other. One tries to suspend a tab while another tries to discard it. You get weird behavior, duplicate suspension pages, and sometimes higher memory usage than having no extensions at all. Pick one approach and commit to it.

Running too many extensions in general is a problem that tab management cannot fix. If you have 30 extensions installed and 20 of them are running background scripts, you have a baseline memory cost of 300-500 MB before you even open a single web page. According to DebugBear’s research, extensions that intercept web requests can significantly slow the browser, and some categories of extensions are worse than others. Audit your extensions. Disable what you do not use.

Not using tab groups is a missed opportunity. Even if you have a suspension extension handling the memory problem, tab groups solve the finding-things problem. They are free, built-in, and take about 30 seconds to set up.

Treating every tab as equally important leads to hoarding. If you have not looked at a tab in three days, you are not going to look at it. Bookmark it or send it to OneTab and close it. The internet will still be there when you need it.

Ignoring chrome://discards is a mistake if you are trying to understand what Chrome is doing behind the scenes. This internal Chrome page shows you every tab’s lifecycle state, how long it has been in the background, and whether Chrome has frozen or discarded it. It is the single best debugging tool for understanding Chrome’s native tab management behavior.

My Recommended Setup

After three years of building and testing these tools, here is what I actually run on my own machines.

Chrome Memory Saver: enabled, with exceptions for Gmail, Slack, and my development server. This handles the baseline. Chrome is reasonably smart about which tabs to discard and when.

Tab Suspender Pro: installed with a 30-minute timeout. This catches the tabs that Memory Saver leaves alone, particularly tabs I visited recently enough that Chrome does not consider them “inactive” but that I am not actually using. The 30-minute threshold is aggressive enough to keep memory in check without suspending tabs I am actively switching between.

Tab Groups: four permanent groups (Work, Docs, Research, Personal), collapsed when not in use. This is organizational, not technical, but it keeps me sane.

A bookmark folder called “Tab Graveyard” for anything I want to save but do not need open. Before I close my laptop at the end of the day, I do a quick sweep and move anything non-essential into this folder. It takes 60 seconds and usually frees 8-12 tabs.

This combination keeps my Chrome memory usage under 3 GB with 25-40 active tabs on a typical workday. That is a workable number on a 16 GB machine that also needs to run VS Code, a local dev server, Docker, and occasionally Figma.

The setup is not flashy. It does not require any paid tools or complex configuration. It just works.

Frequently Asked Questions

Does suspending a tab lose my form data or scroll position?

It depends on the extension. Most suspension extensions, including Tab Suspender Pro and The Marvellous Suspender, will reload the page from scratch when you unsuspend a tab. This means unsaved form data will be lost. The Marvellous Suspender has form detection that can skip tabs where you have input, which helps. Chrome’s native Memory Saver discard behavior also loses form state. If you are in the middle of filling something out, pin the tab or add it to your whitelist.

Is OneTab safe? I heard about The Great Suspender malware issue.

OneTab and The Great Suspender are different extensions by different developers. The Great Suspender was compromised after being sold to a new owner who injected tracking code. OneTab has not had a similar incident and has been maintained by the same developer since 2013. That said, any extension you install has access to your browsing data, so check permissions carefully and favor open-source tools where you can read the code yourself.

Why does Chrome still use a lot of RAM even with Memory Saver on?

Memory Saver only discards background tabs after they have been inactive for a while. Your active tab, pinned tabs, tabs playing audio, and tabs with active WebSocket connections are generally excluded. The Chrome browser process itself, the GPU process, and your extensions also consume memory that Memory Saver does not touch. If Chrome is still heavy after enabling Memory Saver, check chrome://discards to see which tabs are actually being discarded and review your extension list for memory hogs.

Can I use tab groups and a suspension extension together?

Yes, and I recommend it. They solve different problems. Tab groups organize your tabs visually so you can find things. Suspension extensions reduce memory usage by unloading tabs you are not using. They work well together. The one thing to watch for is that some suspension extensions replace the tab content with a placeholder page, which might change the tab’s title in a way that makes your groups less useful. Tab Suspender Pro preserves the original tab title to avoid this.

How many tabs is “too many”?

There is no universal number. It depends on your machine’s RAM, what sites you have open, and how many extensions you are running. As a rough guide: on a machine with 8 GB of RAM, you will start feeling pain around 20-30 tabs without any management tools. On 16 GB, you can comfortably run 40-60 tabs with Memory Saver enabled. On 32 GB, tab count is rarely the bottleneck. The real question is not “how many tabs can I open” but “how many tabs am I actually using right now.” Everything else should be suspended, discarded, or bookmarked.
